## Phase 2: Host OS Log Timezone Fix & Rolling Window Lookup

### The Timezone Offset Bug & Root Cause
* **Symptom**: Previously, all `os_*` columns (`os_event_volume`, `os_severity_max`, etc.) evaluated to `0.0`.
* **Root Cause**: Parsing JSON ISO timestamps (`2026-06-08T11:39:24.759+0530`) with `pd.to_datetime(..., utc=True)` subtracted 5 hours 30 minutes to convert to UTC (`06:09:24`), creating a 5.5-hour mismatch against the naive local time CSV timestamps (`11:39:32`).

### The Fix & 11-Second Rolling Window
1. **Timezone Alignment**: Parsed JSON timestamps as local wall-clock string (`str(raw_ts)[:19].replace('T', ' ')`), ensuring perfect synchronization between network CSVs and OS JSONs.
2. **1-Second Continuous Grid**: Constructed a 1-second continuous timestamp grid across each scenario duration.
3. **11-Second Centered Rolling Window**: Aggregated OS event counts and maximum severity levels over an 11-second centered rolling window ($\pm 5$ seconds around each network flow timestamp) using `pd.merge_asof(direction='nearest')`.

### OS Log Features Created
* `os_event_volume`: Total count of OS log events in the 11-second window.
* `os_severity_max`: Maximum rule severity level (0–15).
* `os_severity_sum`: Sum of rule severity levels.
* `os_sysmon_proc_cnt`: Count of Sysmon process creation/injection events (Rule IDs 61618, 61634).
* `os_pam_sudo_cnt`: Count of PAM sudo/privilege escalation attempts (Rule IDs 5501, 5502, 5402).
* `os_high_severity_cnt`: Count of high-severity alerts ($\ge 7$).

**Validation Result**: **50,015 flows (33.52% of the dataset)** were successfully enriched with non-zero host OS security context!

## Phase 3: Flow-Level Preserved Aggregation (Option B)

Rather than aggregating network flows into artificial 10-second time buckets (which destroys microsecond packet timing differences), we selected **Option B (Flow-Level Enrichment)**:
- Preserved 100% of individual raw network flow conversations.
- Attached the host OS security context to each flow via `asof` time lookup.

## Phase 4: Stratified Time Subsampling (20,000 Flow Cap)

### The Class Imbalance Challenge
Raw `Hulk.csv` contained **421,880 flows** occurring across just **52 seconds** (up to 20,432 flows/second). Including 421k DoS rows would cause extreme class imbalance and distort model training. Similarly, `Discov`, `Ransac`, `Nmap`, and `SlowLoris` had high flow counts ($> 40,000$).

### The Subsampling Algorithm
Applied **Stratified Time Subsampling** per second:
1. Grouped flows by second (`dt_sec`).
2. Calculated the sampling fraction per second: $\text{frac} = \frac{20,000}{\text{Total Raw Flows}}$.
3. Sampled proportionally from every single second of the attack duration with random seed `42`.

**Result**: Reduced `Hulk`, `Discov`, `Ransac`, `Nmap`, and `SlowLoris` down to **20,000 flows** each, preserving the temporal structure of the attack while achieving class balance!

## Phase 5: Dead Flow & Sparsity Cleaning

### 1. Removing Dead / Empty Connection Attempts
Filtered out **8,100 dead flows** where `flow_duration == 0`, `flow_byts_s == 0`, and `flow_pkts_s == 0`. These represent dropped SYN packets or failed TCP handshakes that contained no metric data.

### 2. High Zero Sparsity Removal
Filtered out any rows where $> 70\%$ of feature columns were zero.

## Phase 7: Feature Transformations & Categorical Encodings

### 1. Ports to Categorical One-Hot Encodings
Converted raw numeric port numbers into one-hot binary indicator columns:
* **Destination Ports**: `dst_port_443`, `dst_port_53`, `dst_port_80`, `dst_port_7680`, `dst_port_8888`, `dst_port_1514`, `dst_port_22`, `dst_port_3389`, `dst_port_other`.
* **Source Ports**: `src_port_ephemeral` ($\ge 1024$), `src_port_wellknown` ($< 1024$), `src_port_443`, `src_port_80`, `src_port_53`.
* Raw `src_port` and `dst_port` numbers dropped.

### 2. Protocol to Categorical One-Hot Encodings
* One-hot encoded into `proto_tcp`, `proto_udp`, `proto_other`.
* Raw numeric `protocol` dropped.

### 3. IP Address & Timestamp Removal
* Removed `src_ip`, `dst_ip`, `timestamp`, and `dt_sec` to prevent models from memorizing static IP addresses or temporal offsets.

### 4. Clean Fixed 6-Decimal Export
* Rounded all floating-point features to 6 decimal places and exported using `float_format='%.6f'` to eliminate scientific `E` notation strings from the CSV.
